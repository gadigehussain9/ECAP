# 1. Purpose

This document defines the standards for Retrieval-Augmented Generation (RAG) within the Enterprise Commerce & AI Platform (ECAP).

The objectives are to:

- Improve answer accuracy
- Reduce hallucinations
- Enable enterprise knowledge retrieval
- Support traceable AI responses
- Improve maintainability
- Ensure secure access to organisational knowledge

These standards apply to every AI feature that retrieves external knowledge before generating a response.

---

# 2. What is RAG?

Retrieval-Augmented Generation combines:

- Large Language Models (LLMs)
- Enterprise knowledge sources
- Semantic search
- Vector search
- Prompt engineering

Instead of relying only on the model's internal knowledge, ECAP retrieves relevant documents and provides them as context to the model.

# 4. Supported Knowledge Sources

Examples include:

- Product catalogue
- Product manuals
- Company policies
- FAQs
- Support articles
- Inventory information
- Pricing documents
- Vendor documentation
- Internal knowledge base
- Marketing content

Knowledge sources must be approved and governed.

---

# 5. Document Ingestion

The ingestion pipeline should:

1. Validate documents.
2. Extract text.
3. Remove unsupported content.
4. Normalise formatting.
5. Generate metadata.
6. Split into chunks.
7. Generate embeddings.
8. Store chunks in Azure AI Search.

---

# 6. Chunking Standards

Documents should be split into logical chunks.

Guidelines:

- Preserve paragraph boundaries where practical.
- Avoid splitting tables and lists mid-section.
- Include overlap between adjacent chunks.
- Store document hierarchy (document, section, page).

Chunking strategy should be configurable and validated using evaluation datasets.

---

# 7. Metadata Standards

Every indexed chunk should include metadata such as:

- DocumentId
- DocumentName
- Section
- Source
- Category
- Language
- Version
- Owner
- CreatedDate
- LastModified
- AccessLevel

Metadata supports filtering, auditing and citations.

---

# 8. Embeddings

Embeddings should:

- Use an approved embedding model.
- Be regenerated when the source document changes.
- Be versioned.
- Be stored with metadata.

Do not mix embeddings generated by incompatible models in the same index without a migration strategy.

---

# 9. Search Strategy

Preferred retrieval order:

1. Metadata filters
2. Hybrid Search (Keyword + Vector)
3. Semantic Ranking (where enabled)
4. Top-K selection
5. Prompt construction

Avoid vector-only retrieval when hybrid search provides better relevance.

---

# 10. Prompt Construction

The prompt should contain:

- System prompt
- User question
- Retrieved context
- Constraints
- Expected output format

Only relevant retrieved content should be included.

---

# 11. Context Window Management

Applications should:

- Respect model context limits.
- Prioritise the highest-ranked chunks.
- Remove duplicate information.
- Optimise token usage.

Never exceed the model's supported context window.

---

# 12. Citations

AI responses should reference retrieved sources where appropriate.

Example:

```
Source:

Product Manual

Section 4.2
```

Avoid fabricated references.

---

# 13. Hallucination Prevention

The model should be instructed to:

- Answer only using supplied context.
- Admit when information is unavailable.
- Avoid guessing.
- Clearly distinguish retrieved facts from generated summaries.

---

# 14. Security

Retrieved documents must respect access control.

The retrieval layer shall:

- Enforce user permissions.
- Filter restricted documents.
- Prevent cross-tenant access.
- Apply data classification rules.

Retrieval must never bypass application authorization.

---

# 15. Prompt Injection Protection

Treat retrieved documents and user input as untrusted.

The application should:

- Separate system instructions from retrieved content.
- Ignore embedded instructions in retrieved documents.
- Validate tool requests.
- Restrict privileged operations.

---

# 16. Freshness

Knowledge should be updated through scheduled or event-driven ingestion.

When documents change:

- Re-index affected content.
- Regenerate embeddings where required.
- Update metadata.

---

# 17. AI Response Validation

Responses should be evaluated for:

- Grounding
- Relevance
- Completeness
- Accuracy
- Safety
- Citation quality

Business-critical responses may require additional validation before use.

---

# 18. Observability

Capture telemetry including:

- Query text (subject to privacy rules)
- Retrieved document count
- Search latency
- LLM latency
- Total request duration
- Prompt version
- Embedding model
- Completion model
- Token usage
- Citation count

Use correlation IDs for end-to-end tracing.

---

# 19. Evaluation

Maintain evaluation datasets containing representative user questions.

Measure:

- Precision
- Recall
- Groundedness
- Citation accuracy
- Response quality
- Latency

Evaluate changes before promoting them to production.

---

# 20. Performance Targets

Recommended targets:

| Metric | Target |
|--------|--------|
| Retrieval latency | <300 ms |
| Total AI response | <5 seconds |
| Top-K retrieval | 5–10 documents (tune as needed) |
| Failed retrieval rate | <1% |

Targets should be reviewed using production telemetry.

---

# 21. Cost Optimisation

Reduce cost by:

- Retrieving only relevant chunks.
- Removing duplicate context.
- Using smaller embedding requests where appropriate.
- Caching frequent retrieval results.
- Monitoring token consumption.

---

# 22. Failure Handling

If retrieval fails:

- Return a clear, user-friendly message.
- Log the failure.
- Do not fabricate an answer.
- Retry transient failures where appropriate.
- Trigger alerts for persistent issues.

# 24. Best Practices

- Prefer hybrid search.
- Keep chunks meaningful.
- Use metadata filters.
- Version prompts and embeddings.
- Monitor retrieval quality.
- Test with real business questions.
- Protect sensitive knowledge.
- Review retrieval metrics regularly.

---

# 25. Anti-Patterns

Avoid:

- Sending entire documents to the model.
- Ignoring metadata filters.
- Mixing unrestricted and restricted content.
- Returning uncited answers for knowledge-based queries.
- Overloading prompts with irrelevant context.
- Trusting retrieved content without validation.
